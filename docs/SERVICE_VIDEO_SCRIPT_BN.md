# FlexiTaka সেবা-ব্যাখ্যা ভিডিও — ভয়েস ওভার স্ক্রিপ্ট ও সিন-প্ল্যান
## (Marketplace কনসেপ্ট — সম্পূর্ণ নতুন ভার্সন)

> **⚠️ এই ডকুমেন্ট আগেরটির প্রতিস্থাপন।** আগের ভার্সনে FlexiTaka-কে ভুলভাবে "SIM-এর টাকা সরাসরি ক্যাশে বদলে দেয়" ধরনের একটি সার্ভিস হিসেবে দেখানো হয়েছিল। সেটি **ভুল কনসেপ্ট** ছিল। এখন আপনার দেওয়া আসল কনসেপ্ট অনুযায়ী সম্পূর্ণ নতুন করে লেখা —
>
> **FlexiTaka = SIM Balance Value Marketplace + Discounted Recharge Platform।**
> একজনের অব্যবহৃত SIM balance-এর **value** আর অন্য একজনের কম দামে **recharge-এর প্রয়োজন** — এই দুইয়ের **match**।
>
> **অবস্থা:** এটি **স্ক্রিপ্ট ও সিন-প্ল্যান**। ভিডিওটি **এখনো রেন্ডার করা হয়নি** — আপনার দেওয়া ভয়েস ফাইল পেলে রেন্ডার করা হবে।

## ৪. প্রতিটি লাইনের প্রকৃত দৈর্ঘ্য — TTS চালিয়ে মাপা

**পদ্ধতি:** প্রতিটি লাইন আলাদা করে Google Cloud TTS-এ পাঠানো হয়েছে — ভাষা `bn-IN`, ভয়েস `bn-IN-Wavenet-A`, গতি **১.০০**। তারপর `ffprobe` দিয়ে প্রকৃত দৈর্ঘ্য মাপা হয়েছে। **এগুলো অনুমান নয় — প্রকৃত ফাইল থেকে পড়া সংখ্যা।**

```bash
$ for f in svc5_l01 svc4_l02 svc5_l03 svc3_l05 svc3_l06 \
           svc3_l07 svc3_l08 svc3_l09 svc5_l09 svc3_l11; do
    ffprobe -v error -show_entries format=duration,bit_rate \
      -of default=noprint_wrappers=1 audios/$f/$f.mp3 | tr '\n' ' '
    echo " <= $f"
  done
```

| `s7` | 28.10 → 32.40 | 4.30s | লাইন ৭ |

| `s9` | 36.70 → 40.70 | 4.00s | লাইন ৯ |

**যোগফল = ৪৫.০ সেকেন্ড** ✓

### প্রতিটি সিনে কী দেখা যাবে

**`s1` — 0.00 → 5.90 · সমস্যা**
- **ভিজ্যুয়াল:** পর্দা **দুই ভাগে** বিভক্ত। বাঁ দিকে একটি SIM কার্ড, তার উপরে জমে থাকা ব্যালেন্সের সংখ্যা, নিচে লেখা **`অব্যবহৃত`**। ডান দিকে একটি recharge স্ক্রিনের রূপরেখা, উপরে **`৳`** আর টাকার অঙ্ক বাড়তে থাকা, নিচে লেখা **`প্রয়োজনের বেশি?`**
- **পর্দার লেখা:** `সিমে অব্যবহৃত ব্যালেন্স` (বাঁ) · `কম দামে রিচার্জ?` (ডান)
- **অ্যানিমেশন:** দুই পাশ আলাদা আলাদা ঢুকে দাঁড়ায়, তারপর মাঝখানে একটি নীরব ফাঁক দেখা যায় — যা বোঝায় "এই দুইয়ের মধ্যে কোনো যোগ নেই"।
- **শেষে:** একটি সরু হলুদ রেখা দুই পাশের মাঝখানে বরাবর আঁকা হয় → পরের সিনে সেখানেই FlexiTaka আসবে।

**`s2` — 5.90 → 9.60 · FlexiTaka কী**
- **ভিজ্যুয়াল:** মাঝখানে **FlexiTaka লোগো** দেখা দেয়, তার নিচে ছোট ক্যাপসুলে **`MARKETPLACE`**।
- **পর্দার লেখা:** `দুই প্রয়োজন, এক জায়গায়`
- **অ্যানিমেশন:** লোগো নিচ থেকে উঠে আসে, আর `s1`-এর দুই পাশ থেকে দুটি হলুদ কণা মাঝখানে এসে মেলে — অর্থাৎ জায়গাটাই যোগ করছে।

**`s3` — 9.60 → 15.60 · দুই প্রবাহ (মূল ভিজ্যুয়াল)**
- **ভিজ্যুয়াল:** মাঝখানে **FlexiTaka লোগো**। **বাঁ দিকে** একটি কার্ডে SIM balance-এর value, **ডান দিকে** একটি কার্ডে recharge-এর প্রয়োজন। দুই দিক থেকে দুটি তীর **মাঝখানে** এসে মেলে।
- **পর্দার লেখা (নিচে বাঁ → ডান):**
  - বাঁ: **`Unused / Extra SIM Balance`** → **`Cash Value`**
  - ডান: **`Customer`** → **`Discounted Recharge`**
  - মাঝে: **`FlexiTaka`**
- **অ্যানিমেশন:** তীরদুটি দুই দিক থেকে বেরিয়ে মাঝখানে মিলে যায় → একটি **ding** বাজে, লোগোর চারপাশে সবুজ আভা ছড়ায়।
- **এই সিনটাই ভিডিওর প্রাণ** — match হওয়ার ধারণা এখানেই সবচেয়ে স্পষ্ট।

**`s4` — 15.60 → 20.10 · প্রবাহ ১ — যিনি ছাড়বেন**
- **ভিজ্যুয়াল:** একটি অ্যাপ কার্ড। উপরে একটি নম্বরের ফিল্ড, নিচে ব্যালেন্সের অঙ্ক আর একটি **`অফার করুন`** বোতাম।
- **পর্দার লেখা:** `১. ব্যালেন্স অফার করুন`
- **অ্যানিমেশন:** অঙ্কটি টাইপ হয়, তারপর বোতামে চাপ → click → হলুদ কণা বেরিয়ে FlexiTaka-র দিকে যায়।

**`s5` — 20.10 → 24.10 · প্রবাহ ১ এর ফল — cash value**
- **প্রবাহ:** ১ · **ভয়েস লাইন:** ৫
- **ভিজ্যুয়াল:** বাঁ দিকে SIM কার্ড (হালকা হয়ে যাচ্ছে), ডান দিকে একটি ওয়ালেট কার্ড, মাঝখানে FlexiTaka লোগো। কণাগুলো ডান দিকে গিয়ে পড়ে।
- **পর্দার লেখা:** `নির্ধারিত ক্যাশ ভ্যালু`
- **অ্যানিমেশন:** কণা পৌঁছালে **ding**, ওয়ালেট কার্ডে দাগ পড়ে।

> **সতর্কতা:** এখানে কোনো নির্দিষ্ট রেট, পরিমাণ বা সময় বলা হয়নি। পর্দার লেখাও "নির্ধারিত" — অর্থাৎ যা পরে নির্ধারণ করা হবে।

**`s6` — 24.10 → 28.10 · প্রবাহ ২ — যিনি নেবেন**
- **প্রবাহ:** ২ · **ভয়েস লাইন:** ৬
- **ভিজ্যুয়াল:** একটি recharge স্ক্রিন, উপরে স্বাভাবিক দাম আর তার নিচে **কম দামে** একটি লাইন, মাঝে একটি সবুজ তীর।
- **পর্দার লেখা:** `২. ডিসকাউন্টেড রিচার্জ`
- **অ্যানিমেশন:** দামের সংখ্যা উপরের সারি থেকে নিচের সারিতে গড়িয়ে নামে, কমতে থাকে → **ding**।

**`s7` — 28.10 → 32.40 · কীভাবে কাজ করে — শুরু**
- **ভিজ্যুয়াল:** ফোনের স্ক্রিন। উপরে একটি নম্বরের ফিল্ড, নিচে ছোট একটি ধাপ-তালিকা।
- **পর্দার লেখা:** `নম্বর দিয়ে লগইন` · নিচে ছোট করে `১ · ২ · ৩ · ৪` (ধাপের সংখ্যা)
- **অ্যানিমেশন:** কার্সর নম্বর টাইপ করে, তারপর একটি রিং ঘুরে সম্পন্ন হয় → **click**।

**`s8` — 32.40 → 36.70 · সুবিধা ও নিরাপত্তা**
- **ভিজ্যুয়াল:** একটি প্যানেল, ভেতরে তিনটি সারি — প্রতিটির পাশে একটি ছোট সবুজ আইকন।
- **পর্দার লেখা:** `হিস্ট্রি` · `লিমিট` · `ফ্রড-কন্ট্রোল`
- **অ্যানিমেশন:** তিনটি সারি একের পর এক পড়ে, প্রতিটিতে হালকা **click**।

**`s9` — 36.70 → 40.70 · লক্ষ্য**
- **ভিজ্যুয়াল:** শান্ত সবুজ ব্যাকগ্রাউন্ড, মাঝখানে তিনটি শব্দ একটি করে আলোকিত হয়।

**`s10` — 40.70 → 45.00 · এন্ড কার্ড**

## ৬. দুই প্রবাহ — ভিজ্যুয়ালে যেভাবে দেখানো হবে

আপনার দেওয়া concept অনুযায়ী দুটি প্রবাহ, এবং সিন-প্ল্যানে কোথায় বসছে:

```
প্রবাহ ১ (Seller)  —  s3 (বাঁ)  ·  s4  ·  s5

    Unused / Extra SIM Balance
              │
              │  (value offer)
              ▼
          FlexiTaka  ──────►  Cash Value for Seller

প্রবাহ ২ (Buyer)   —  s3 (ডান)  ·  s6

        Customer
              │
              │  (recharge needed)
              ▼
     Discounted Recharge  ──────►  FlexiTaka
```

**মূল ধারণা (সিন ০৯.৬০–১৫.৬০ সেকেন্ডে যা দেখা যাবে):**
- একদিকের **অব্যবহৃত value** আর অন্যদিকের **recharge চাহিদা** — দুটোই একই telecom ecosystem-এর ভেতরে
- মাঝখানে **FlexiTaka** শুধু মেলায়, নিজে কিছু বানায় না
- তাই value নষ্ট হয় না, বরং অন্য কারো কাজে লাগে

**যা দেখানো হবে না:** FlexiTaka-কে "balance transfer" সার্ভিস হিসেবে দেখানো হবে না। কোনো ব্যাংক/ওয়ালেটের নির্দিষ্ট নামও নয়।

## ৭. ট্রানজিশন ও সাউন্ড ইফেক্ট

| কখন | ইফেক্ট | কেন |
|---|---|---|
| `s1` → `s2` | **riser** | দুই প্রয়োজন মিলতে যাচ্ছে — টান তৈরি |
| `s2` → `s3` | **whoosh** | মাঝ থেকে দুই দিকে ছড়ানো |
| `s3`-এ তীর মেলার মুহূর্ত | **ding** | মূল মিলন — ভিডিওর সবচেয়ে গুরুত্বপূর্ণ বিট |
| `s4`-এ বোতাম চাপ | **click** | UI অ্যাকশন |
| `s5`-এ কণা পৌঁছানো | **ding** | ক্যাশ ভ্যালু পৌঁছাল |
| `s6`-এ দাম নামা | **ding** | ডিসকাউন্ট |
| `s7`-এ লগইন সম্পন্ন | **click** | UI অ্যাকশন |

**অডিও লেভেল (ভয়েস যোগ হলে নতুন করে ব্যালান্স করতে হবে):**

> **ℹ️ লক্ষ্য করুন — ভিডিওতে ভয়েস যোগ হলে কোনো সাউন্ড ইফেক্ট আলাদা করে বসাতে হবে না।** কিটে SFX স্নাইপগুলো **সিনের সময়ের সাপেক্ষে** (scene-relative) লেখা থাকে, তাই আপনি যদি কোনো সিন লম্বা-ছোট করেন, ইফেক্টগুলোও নিজে থেকেই ঠিক জায়গায় সরে যায়। এটাই আগের ডকুমেন্টে ভেরিফাই করা হয়েছিল — নতুন সিন যোগ করার পরেও `at 20.020s` নিজে থেকে ঠিক জায়গায় বসেছিল।

| স্তর | আগের (ভয়েস ছাড়া) | ভয়েস যোগ হলে প্রস্তাবিত |
|---|---|---|
| মিউজিক | −9 dB | **−15 dB** (ভয়েসের নিচে ডাক করা) |
| SFX বাস | −6 dB | **−9 dB** |
| ভয়েস | নেই | **−3 dB** (নেতৃত্বে) |
| Ducker side-chain | SFX বাস | **ভয়েস** |
| লক্ষ্য | −16.8 LUFS | **−16.0 LUFS**, true peak ≤ **−1.5 dBTP** |

## ৯. রেডি-টু-কপি প্লেইন টেক্সট

**ক-রূপ — সময় সহ (রেফারেন্সের জন্য):**


## ১১. ⚠️ ট্রেডমার্ক ও আইনি সতর্কতা

**এই ভিডিওতে কোনো অপারেটরের নাম বা লোগো নেই — আপনার নির্দেশ অনুযায়ী।** শুধুমাত্র **FlexiTaka** নিজের ব্র্যান্ড।

- **FlexiTaka** — আপনার নিজের ব্র্যান্ড, লোগো ১০০% অপরিবর্তিত
- **কোনো অপারেটরের নাম নেই** — bKash, Robi, BanglaLink, Grameenphone — একটি৩ কোথাও নেই (না লেখায়, না ভিজ্যুয়ালে, না সাউন্ডে)
- ভবিষ্যতে কোনো অপারেটরের নাম/লোগো দেখাতে চাইলে **সংশ্লিষ্ট ব্র্যান্ডের লিখিত অনুমতি** নেওয়া প্রয়োজন
- **কোনো নির্দিষ্ট রেট, সময় বা গ্যারান্টির দাবি নেই** — কারণ কোন balance eligible হবে, transaction limit কত হবে, settlement কীভাবে হবে — এসব বাস্তব implementation-এর আগে নির্ধারিত হবে
- **লেখা/ভয়েসে কোনো আইনি প্রতিশ্রুতি নেই** — "নির্ধারিত ক্যাশ ভ্যালু" কথাটি সচেতনভাবে বেছে নেওয়া, যাতে কিছু গ্যারান্টি না করা হয়

## ১২. পরের ধাপ — আপনি ভয়েস দিলে ভিডিও বানিয়ে দেব

**এখন শুধু স্ক্রিপ্ট ও সিন-প্ল্যান দরকার, ভিডিও রেন্ডার পরে — আপনার নির্দেশ অনুযায়ী।**

> **ℹ️ আপনার টেক্সট সরাসরি ব্যবহার করলে:** আপনি যদি **হুবহু এই লেখা** TTS-এ দেন (কোনো লাইন যোগ বা বাদ না করেন) — তাহলে §৫-এর সিন-টাইমিং **যেমন আছে তেমনই** কার্যকর হবে; শুধু লাইন ৩-এ **১.০১১x** গতি প্রযোজ্য হবে (§৪.১ দেখুন)। তাই আগের ডকুমেন্টের মতো "সিন ৪-এর লাইন কেটে যাবে" ধরনের কোনো সমস্যা এখানে **নেই** — প্রতিটি লাইন তার নিজের সিনের ভেতরে আরামে বসে যায়।
>
> **এর চেয়ে ছোট বা বড় কিছু পাঠালে:** ডেলিভারির আগে প্রতিটি ফাইলের প্রকৃত দৈর্ঘ্য মেপে নেওয়া হবে, আর দরকার হলে কেবল সেই একটি সিনের দৈর্ঘ্য ঠিক করে দেওয়া হবে — বাকি ভিডিও অপরিবর্তিত থাকবে।

### আপনার দিক থেকে যা দরকার

**১. ভয়েস ফাইল (MP3 বা WAV)** — §৯-এর ১০টি লাইন যেকোনো AI দিয়ে বানিয়ে পাঠান:
- **আলাদা ১০টি ফাইলে** দিলে সবচেয়ে ভালো — প্রতিটি সিনে নিখুঁতভাবে বসবে
- একটি ফাইলেই দিলে অসুবিধা নেই — আমি সময় ধরে কেটে নেব
- ফাইলের নাম দিলে ভালো হয়: `vo_01` … `vo_10`

**২. অথবা শুধু বলুন** — "এই স্ক্রিপ্টেই ভয়েস বানাও" — তাহলে যে ভয়েস দিয়ে দৈর্ঘ্যগুলো মাপা হয়েছে (`bn-IN-Wavenet-A`) সেটি দিয়েই বসিয়ে দেব।

### আমি যা করব

1. `video.config.js`-এ ১০টি সিন সেট করা (§৫-এর সময়ভাগ হুবহু)
2. নতুন দৃশ্য-ধরন লেখা — বিশেষত **সিন ৩-এর দুই-প্রবাহ ম্যাচ ভিজ্যুয়াল**, যা এই ভিডিওর মূল
3. আপনার ভয়েস ফাইল প্রতিটি সিনে বসানো + মিউজিক ডাকিং নতুন করে ব্যালান্স
4. `./render.sh` দিয়ে রেন্ডার
5. **প্রতিটি সিনের ফ্রেম চোখে দেখে** যাচাই — কোনো লেখা বা লোগো আগের সিনে লিক করছে কি না
6. `ffprobe` দিয়ে দৈর্ঘ্য / রেজোলিউশন / ফ্রেম / অডিও স্ট্রিম যাচাই + peak / LUFS / true peak রিপোর্ট
7. MP4 + আলাদা অডিও ডেলিভারি, GitHub-এ push

### এই ভিডিওটির জন্য কী কী কাজ লাগবে

| সিন | দৃশ্য-ধরন | নতুন কোড লাগবে? |
|---|---|---|
| s1 | দুই ভাগের তুলনা (`splitCompare`) | **হ্যাঁ — নতুন** |
| s2 | লোগো রিভিল (বিদ্যমান `logoReveal` থেকে) | ছোট বদল |
| s3 | দুই-প্রবাহ ম্যাচ (`twoSidedMatch`) | **হ্যাঁ — নতুন, সবচেয়ে বড় কাজ** |
| s4, s6, s7 | অ্যাপ স্ক্রিন (`appStep`) | **হ্যাঁ — নতুন** |
| s5 | ফ্লো অ্যানিমেশন (বিদ্যমান `flowToWallet` থেকে) | ছোট বদল |
| s8 | তালিকা (`trustList`) | **হ্যাঁ — নতুন** |
| s9 | শান্ত টাইপোগ্রাফি (`calmTypes`) | ছোট বদল |
| s10 | এন্ড কার্ড (বিদ্যমান) | নেই |

অনুমানিক কাজ: **নতুন ৪–৫টি দৃশ্য-ধরন, ২৫০–৩৫০ লাইন কোড।** একবার লিখে ফেললে এরপর যত সেবা-ব্যাখ্যা ভিডিও চাইবেন, সবই শুধু কনফিগ বদলেই হয়ে যাবে।

## ১৪. কমান্ড রেফারেন্স (রেন্ডারের সময় ব্যবহার হবে)

```bash
# ১০টি লাইনের প্রকৃত দৈর্ঘ্য মাপা
for f in vo_01 vo_02 vo_03 vo_04 vo_05 vo_06 vo_07 vo_08 vo_09 vo_10; do
  printf "%-8s " "$f"
  ffprobe -v error -show_entries format=duration -of csv=p=0 "vo/$f.wav"
done

# কোনো লাইন তার বরাদ্দের চেয়ে বড় কি না দেখা (উদাহরণ: লাইন ৩, বরাদ্দ 5.70s)
ffprobe -v error -show_entries format=duration -of csv=p=0 vo/vo_03.wav   # <= 5.70 হলে ঠিক

# কনফিগ থেকে সময়ভাগ যাচাই — রেন্ডার না করেই, এক সেকেন্ডে
node lib/dump-plan.js

# সম্পূর্ণ রেন্ডার
./render.sh
```
